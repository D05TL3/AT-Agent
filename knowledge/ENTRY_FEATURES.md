# 入口特征填写模板

## 这是什么

"入口特征"= **看到什么，就该先试什么**。它不是解题步骤，是把观测翻译成第一个动作的映射表。

它喂给 `route_planner`，决定它提什么路线。路线错了，后面 executor 的算力全白花。

## 一条好的入口特征长什么样

四元组，缺一不可：

```
信号   ：你在题面上能直接看到/测到的东西
判读   ：它意味着什么（这一步是价值所在）
首选   ：第一个该执行的动作
止损   ：什么情况下立刻放弃这条线
```

### 对照示例

| | 写法 |
|---|---|
| ❌ 废话 | 「测试 SQL 注入」 |
| ✅ 判据 | 信号：`?id=1` 加单引号返回 500，但响应体与正常页一致<br>判读：数据库报错被应用层吞掉，无回显<br>首选：布尔盲注，比较 `and 1=1` 与 `and 1=2` 的响应长度差<br>止损：两种条件的响应长度差 <5 字节且时间无差异 → 不是注入 |

| | 写法 |
|---|---|
| ❌ 废话 | 「检查栈溢出保护」 |
| ✅ 判据 | 信号：`checksec` 显示 Canary found + No PIE + 二进制以 `fork` 方式起服务<br>判读：fork 模型下 canary 在每次连接间可能复用，可逐字节爆破<br>首选：写爆破脚本，从 `\x00` 开始逐位试，观察进程是否仍存活<br>止损：每次爆破后进程重启且 canary 变化 → 不是 fork，放弃爆破 |

## 为什么必须带"判读"和"止损"

只有"信号 + 首选"的话，模型会把它当成万能 pattern 到处套用。
**判读**让它知道这是推理而非规则；**止损**是比赛中最大的失分防线——
模型最常见的失败不是不会做，是在一条不可能的路上耗光时间。

## 两个取材来源

**一、你们打过的题。** 最准。哪怕是"这道题我当时第一眼看错了方向"这种，
写下来就是一条高价值的止损判据。

**二、题面结构。** 不依赖具体题目，只看题目给的东西的形状：

- 给了二进制附件 → 先 `file` + `checksec`，不是先 IDA
- 给了一个 URL 和登录框 → 先确认注册/找回密码这类旁路，不是先爆破
- 给了源码压缩包 → 先找依赖版本和路由表，不是逐行读
- 给了一段密文 + 参数 → 先估参数规模判断是不是标准困难问题
- 给了流量包 → 先 `tshark -z io,phs` 看协议分布，不是逐包读

这类"题面形状 → 第一个动作"的映射，即使没打过对应的题也能写出来，
而且泛化性很好。

## 填好之后怎么用

把内容按 JSON 写进 `knowledge/kb.json` 的 `ref` 段，`tags` 用信号里出现的词：

```json
"ref": [
  {
    "tags": ["单引号", "500", "无回显", "布尔"],
    "stages": ["vuln_localize"],
    "text": "单引号报 500 但响应体一致 → 报错被吞，无回显 → 布尔盲注比较响应长度差；长度差 <5 字节且无时间差则放弃注入方向"
  }
]
```

`tags` 会被拿去和当前状态文本做词面匹配，所以**用你在题面上真会看到的词**，
不要用抽象术语。写"单引号""无回显"比写"SQL 注入"命中率高得多。
